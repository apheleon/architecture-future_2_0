# Обоснование конфигурации инфраструктуры

## Выбор ресурсов и параметров

### Виртуальные машины
- **Медицинский бэкенд (Standard_D4s_v3)**: 4 vCPU, 16GB RAM - оптимально для обработки медицинских данных и веб-нагрузки
- **Финтех-сервисы (Standard_D4s_v3)**: аналогичная конфигурация для равномерного распределения нагрузки
- **ИИ-сервисы (Standard_NC6s_v3)**: GPU-оптимизированная VM с NVIDIA Tesla V100 для ML-работloads

### Диски
- **SSD Premium_LRS**: Высокая IOPS для production workload
- **256GB для веб-сервисов**: Достаточно для ОС, приложений и логов
- **512GB для ИИ-сервисов**: Дополнительное пространство для моделей и временных данных

### Настройки сети
- **NAT Gateway (Standard)**: Обеспечивает исходящий интернет-доступ без статических IP на VM
- **Разделение на подсети**: Изоляция веб-сервисов, БД и аналитики для безопасности
- **NSG правила**: Строгий контроль доступа, только необходимые порты

### Базы данных
- **PostgreSQL для медицинских данных**: Лучшая поддержка JSON и пространственных данных
- **SQL Server для финансовых данных**: Совместимость с существующими системами reporting
- **Yandex Query**: serverless, не нужно думать о размере кластера, вы платим только за объем обработанных данных.

## Причины использования декларативного подхода

1. **Воспроизводимость**: Инфраструктура может быть развернута идентично в dev, staging, prod
2. **Версионность**: Изменения отслеживаются в Git, возможен rollback
3. **Документация**: Код служит живой документацией текущего состояния
4. **Автоматизация**: Исключает человеческие ошибки при ручном развертывании
